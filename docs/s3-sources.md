# S3 Buckets, Layout & Schema Reference

Reference guide for S3 bucket structures, file partitioning, and raw event schemas generated by Kiro (Amazon Q Developer) across AWS accounts.

---

## AWS Accounts & Setup

Accounts are configured in `conf/accounts.json` (see `conf/accounts.json.example`).

| Profile | Account ID | Label | Description |
|---|---|---|---|
| `111111111111_AdministratorAccess` | `111111111111` | **prod** | Production AWS deployment |
| `222222222222_AdministratorAccess` | `222222222222` | **dev** | Development AWS deployment |

If both accounts are connected to the same AWS IAM Identity Center directory, users share Identity Center identities across both accounts. The sync pipeline tags every row with `aws_account_id` and `account_label` so you can slice or aggregate across accounts.

## S3 Buckets & Folder Structure

### 1. Daily CSV Reports — `user_report` & `by_user_analytic`

Both accounts write daily CSV reports to identical directory structures:

```
s3://my-org-kiro-usage-activity-report/              (prod · 111111111111)
s3://my-org-kiro-usage-report-dev/                    (dev  · 222222222222)
│
└── reports/
    └── AWSLogs/<account-id>/KiroLogs/
        │
        ├── user_report/us-east-1/<YYYY>/<MM>/<DD>/00/
        │   ├── KIRO_IDE_<account-id>_user_report_<YYYYMMDDHHmm>.csv
        │   ├── KIRO_CLI_<account-id>_user_report_<YYYYMMDDHHmm>.csv
        │   └── PLUGIN_<account-id>_user_report_<YYYYMMDDHHmm>.csv      (dev only — prod has no PLUGIN client type)
        │
        └── by_user_analytic/us-east-1/<YYYY>/<MM>/<DD>/00/
            └── <account-id>_by_user_analytic_<YYYYMMDDHHmm>_report.csv
```

#### Report Content Summaries

- **`user_report`**: High-level credit, message count, and model usage per user and client type.
  - Key columns: `Date, UserId, Client_Type, Chat_Conversations, Credits_Used, Overage_Cap, Overage_Credits_Used, Overage_Enabled, ProfileId, Subscription_Tier, Total_Messages, New_User, User_Email, <model>_messages...`
  - Note: Dev account includes newer model columns (e.g. `auto`, `claude_opus_4.6/4.8/5`, `claude_sonnet_4.5/4.6/5`, `gpt_5.6_luna/sol`, `qwen3_coder_next`).
- **`by_user_analytic`**: Granular feature activity per user (46 columns).
  - Key columns: `UserId, Date, Chat_*, CodeFix_*, CodeReview_*, Dev_*, DocGeneration_*, InlineChat_*, Inline_*, TestGeneration_*, Transformation_*`

*(For full column-by-column definitions, see [Data Dictionary](data-dictionary.md).)*

## 2. Prompt Logs — Full Conversation Content

Prompt logs capture live model invocations and completions.

```
s3://my-org-kiro-usage-report/                         (prod · 111111111111)
└── Prompt_Logging/Prompt_Logging/AWSLogs/111111111111/KiroLogs/
    └── GenerateAssistantResponse/us-east-1/<YYYY>/<MM>/<DD>/<HH>/
        └── 111111111111_GenerateAssistantResponse_<YYYYMMDDHHmm>_<id>.json.gz
        (STOPPED after 2026-07-31 in prod)

s3://my-org-kiro-usage-report-dev/                      (dev  · 222222222222)
└── prompt-logs/AWSLogs/222222222222/KiroLogs/
    ├── GenerateAssistantResponse/us-east-1/<YYYY>/<MM>/<DD>/<HH>/
    │   └── 222222222222_GenerateAssistantResponse_<YYYYMMDDHHmm>_<id>.json.gz
    │
    └── GenerateCompletions/us-east-1/<YYYY>/<MM>/<DD>/<HH>/           (dev only — inline completions)
        └── 222222222222_GenerateCompletions_<YYYYMMDDHHmm>_<id>.json.gz
```

### JSON Schema (gzipped `.json.gz`)

Each compressed file contains a JSON envelope with one or more records:

```json
{
  "records": [
    {
      "generateAssistantResponseEventRequest": {
        "prompt": "How do I parse JSON in Python?",
        "chatTriggerType": "MANUAL",
        "userId": "d-d0d0d0d0d0.aaaaaaaa-1111-2222-3333-444444444444",
        "timeStamp": "2026-07-18T00:22:17.156616451Z",
        "modelId": "claude-opus-4.6"
      },
      "generateAssistantResponseEventResponse": {
        "assistantResponse": "You can use Python's built-in `json` module...",
        "codeReferenceEvents": [],
        "requestId": "f81d4fae-7dec-11d0-a765-00a0c91e6bf6"
      }
    }
  ]
}
```

> **High Volume Warning**: Prompt logs can reach hundreds of thousands of files in busy accounts. Always download with `--date <YYYY-MM-DD>` when testing or doing incremental runs.

## Local Mirror Layout

When downloaded via `s3_sync.py` or `main.py`, files are saved to `data/<account_id>/` preserving their source account segregation:

```
data/
├── 111111111111/                          # prod
│   ├── .sync_state.json                   # watermark & downloaded-file tracking
│   ├── user_report/
│   │   └── KIRO_IDE_111111111111_user_report_202607300000.csv
│   ├── by_user_analytic/
│   │   └── 111111111111_by_user_analytic_202608240000_report.csv
│   └── prompt_logs/                       # only when --prompt-logs is used
│       └── 111111111111_GenerateAssistantResponse_202607180022_3SOS7oQUc5UOH6k2.json.gz
│
└── 222222222222/                          # dev
    ├── .sync_state.json
    ├── user_report/
    │   ├── KIRO_IDE_222222222222_user_report_202608240000.csv
    │   ├── KIRO_CLI_222222222222_user_report_202608240000.csv
    │   └── PLUGIN_222222222222_user_report_202608240000.csv
    ├── by_user_analytic/
    │   └── 222222222222_by_user_analytic_202608240000_report.csv
    └── prompt_logs/
        └── 222222222222_GenerateAssistantResponse_202608220157_jx1201brM8o2tGoq.json.gz
```

Local files older than `DATA_RETENTION_DAYS` (default 30, configured in `conf/.env.kiro`) are purged automatically at the start of each sync.
